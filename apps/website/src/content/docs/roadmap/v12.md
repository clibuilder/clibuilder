---
title: Roadmap to v12
description: "What clibuilder 12 changes for a CLI author, and which parts you can use in v11 already."
---

`clibuilder` 12 is a breaking release. It makes agent-facing output the default and removes most of
the runtime dependencies. Two accepted RFCs set its design:

- [axi-native](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md): output
  modes, formats, errors and exit codes.
- [slim-dependencies](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/slim-dependencies.md):
  replacing zod and standard-log, and moving plugin support out of core.

This page summarizes the decisions a CLI author needs. The RFCs are the authority. Where a detail
here differs from them, they win.

To upgrade a CLI, follow [Upgrading from clibuilder 11 to 12](/clibuilder/guides/upgrade-to-12/). It
goes through each change in order, with the fix and the codemod.

Each item has one of these labels:

- **Available**: published on npm. You can install it today.
- **Unreleased**: merged on `main`, waiting for the next release. Do not install it from npm yet.
- **Planned**: decided in an RFC, not built yet. The design can still change in its pull request.

`clibuilder` 12 has no release date.

## Output modes: `axi` and `console`

**Unreleased.** `cli({ output: 'axi' | 'console' })` and `cli({ streams })` are on `main` and ship
in 12. `cli({ output })` picks one of two modes. `axi` is the default. Both modes are permanent, and
neither is deprecated. See [Streams and output](/clibuilder/api/cli/#streams-and-output),
[Errors with `output: 'axi'`](/clibuilder/guides/failing/#errors-with-output-axi) and
[Usage errors with `output: 'axi'`](/clibuilder/guides/failing/#usage-errors-with-output-axi).

| | `output: 'axi'` (v12 default) | `output: 'console'` |
| --- | --- | --- |
| Value returned from `run()` | stdout, encoded | not printed |
| Thrown `CliError` | stdout, encoded once | message and help on stderr |
| Usage error | stdout, coded, exit 2 | prose and full help on stderr, exit 2 |
| `--help`, `--version` | stdout | stdout |
| `ui.info`, `ui.debug` | stderr | stdout |
| `ui.warn`, `ui.error` | stderr | stderr |

The `console` column is how `clibuilder` 11 behaves. To keep that behavior in v12, set
`output: 'console'`. Its output is the 11.5.0 output byte for byte, except that the help lists the
global `--format`. Source:
[axi-native section 3.10](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#310-output-modes-and-stream-routing).

## `toon` is the default format

**Unreleased.** The global `--format`, `this.format`, and the startup error for a command's own
`format` option are on `main` for every CLI, in both output modes. See
[The global `--format` option](/clibuilder/api/cli/#the-global---format-option).

Every command accepts a global `--format <toon|json|text>`, and `run()` reads the
resolved value from `this.format`. The default is `toon`. Change it with `cli({ format: 'text' })`.
The format does not change between a terminal and a pipe. A command that declares its own `format`
option is a startup error in v12: delete it and read `this.format`. `-f` is not reserved for
`--format`. A bad `--format` value is a usage error with exit code 2. Source:
[axi-native section 3.4](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#34---format-is-not-first-class-6394).

## `ui.*` goes to stderr in `axi` mode

**Unreleased.** In `axi` mode, the default, every `ui.*` call is a diagnostic on stderr, including
`ui.info`. Answers go to stdout. If a script reads what your command prints with `ui.info`, return
the value from `run()` instead, or use `output: 'console'`.

## Help is an answer

**Unreleased** with `output: 'axi'`, the default: `--help` is an answer on stdout that follows `--format`, text
help under `text` and the structured help under `toon` and `json`. `--version` is plain text in
every format. A command may declare `examples`, shown at the end of its help. `ui.showHelp` and
`ui.showVersion` are deprecated; from `run()` they answer like `--help` and `--version`. See
[`--help` and `--version` with `output: 'axi'`](/clibuilder/api/cli/#--help-and---version-with-output-axi).

A usage error no longer prints the full help in `axi` mode. `showHelp` and `showVersion` stay on
`ui` in 12, deprecated, and are removed in a later major. Source:
[axi-native section 3.7](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#37-help-is-not-agent-shaped-6397).

## Returned values are printed

**Unreleased.** The result channel is on `main`, in the default `axi` mode (see
[The result channel](/clibuilder/api/cli/#the-result-channel)). In `axi` mode, a value other than `undefined` returned from `run()` is printed to
stdout in the resolved format. `parse()` still resolves to it, so tests and programmatic callers see
no change. Return `undefined` to print nothing. `result(value, { help, render })` controls the
printed form, `document(content)` prints content verbatim, and `empty(message)` reports an empty
result with exit code 0. [The codemod](/clibuilder/guides/upgrade-to-12/#run-the-codemod-first) lists every `return <expr>` in a `run()` for review. Source:
[axi-native section 3.5](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#35-no-result-channel-6395).

## Exit codes 0, 1 and 2

**Available** in `clibuilder` 11: `exitCodes` is `{ success: 0, error: 1, usage: 2 }`. See
[Failing](/clibuilder/guides/failing/#exit-codes).

**Planned for v12:** core keeps exactly these three. `CliError.exitCode` accepts any integer from
1 to 255, and 0 is rejected. Neither core nor `@clibuilder/axi` defines named codes above 2. The
exit code says success, failure or usage error. The `code` string on the error says which failure.
Source:
[axi-native section 3.6](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#36-exit-codes-stop-at-012-6396).

## zod is replaced by `t`

**Available** in `args-minus` 0.2.0: the [`t` descriptors](/clibuilder/packages/args-minus/), with
constraints as options, `.optional()`, `.check()`, `t.custom()`, `t.json()` and `parseArgsAsync()`.

**Available** in `clibuilder` 11.5.0: `clibuilder` re-exports `t`, and an argument or option
declared with `t` is converted and checked by `args-minus`. This is not a breaking change: each
declaration is parsed by its own type, so a command can mix `z` and `t`, and `z` declarations
behave as before in 11.5.0. See [`t`](/clibuilder/api/t/).

**Unreleased, in 12:** zod is removed, with the `z` re-export, and `type-plus` and `tersify` with
it. `t` is the only way to declare an option or argument type. `config` takes any
[Standard Schema](https://standardschema.dev), so you can keep zod there as your own dependency.
`js-yaml` becomes an optional peer dependency, loaded only when a YAML config file is read. A clean
install of `clibuilder` drops from 41 packages (19 MB) to 3 (1.2 MB). A
[codemod](/clibuilder/guides/upgrade-to-12/#run-the-codemod-first) rewrites the supported zod calls to `t`, and
[the upgrade guide](/clibuilder/guides/upgrade-to-12/#zod-is-replaced-by-t) lists the behaviour that changes with it. A conversion that reads files, resolves paths, calls
the network or depends on other options moves into `run()`; see
[what belongs in the parser](/clibuilder/packages/args-minus/#what-belongs-in-the-parser-and-what-belongs-in-run).
Source:
[slim-dependencies section 3.4](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/slim-dependencies.md#34-design-c).

## standard-log is removed

**Unreleased, in 12.** `clibuilder` no longer depends on standard-log and standard-log-color. Every
CLI writes through the built-in UI to
[`cli({ streams: { stdout, stderr } })`](/clibuilder/api/cli/#streams-and-output), which defaults to
`process.stdout` and `process.stderr`. `--verbose`, `--silent` and `--debug-cli` work as before, and
[`testCommand()`](/clibuilder/api/test-command/) still returns `messages`, one line per message.

With `output: 'console'`, `info` and `debug` still go to stdout, and `warn` and `error` to stderr. What
changes from `clibuilder` 11.5.0:

- **Colour only on a terminal.** `error` is red and `warn` is yellow only on a stream that is a TTY,
  following `NO_COLOR` and `FORCE_COLOR`. In 11.5.0 standard-log-color wrapped clibuilder's own
  `error` and `warn` text in colour codes even when stderr was a pipe or a file. To migrate: if a
  script or a test matched those escape codes, match the plain text.
- **No `clibuilder` prefix.** clibuilder's own messages, such as those shown with `--debug-cli`, no
  longer start with `clibuilder`. To migrate: match the message without the prefix.

No code change is needed otherwise. If you want standard-log, pino or another logger, wrap it in a
function your commands call. Source:
[slim-dependencies section 4](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/slim-dependencies.md#4-logging-standard-log-and-standard-log-color).

## Plugins move to `@clibuilder/plugins`

**Available:** [`@clibuilder/plugins`](/clibuilder/packages/plugins/) 0.1.0 and the
[`use()` hook](/clibuilder/api/cli/#useextension) in `clibuilder` 11.5.0. A v11 CLI can switch with
`.use(plugins())`.

**Unreleased:** `clibuilder` 12 has no plugin support in core. It is on `main` and ships in 12.
This is a breaking change:

- The `config` option of `cli()` is removed. `.use(config())` from `clibuilder/config` loads the
  config for the commands only. It no longer loads the plugins that
  the config's `plugins` key names.
- The `keywords` option of `cli()` and `this.keywords` in `run()` are removed. Keywords are an
  option of `plugins({ keywords })`, and default to the CLI's name.
- The `plugins` command group (`plugins list`, `plugins search`) is no longer added when `config`
  or `keywords` is set. `plugins()` adds it. Pass `command: false` to opt out.
- `clibuilder` 12 no longer depends on `import-meta-resolve`, `find-installed-packages` or
  `search-packages`. `@clibuilder/plugins` owns them.

To migrate, add `@clibuilder/plugins` and one call to `.use()`:

```diff
- cli({ name: 'my-cli', version: '1.0.0', config: true, keywords: ['my-cli-plugin'] })
+ cli({ name: 'my-cli', version: '1.0.0' })
+   .use(config())
+   .use(plugins({ keywords: ['my-cli-plugin'] }))
```

Import `plugins` with `import { plugins } from '@clibuilder/plugins'`, and `config` with
`import { config } from 'clibuilder/config'`. Add `config()` before `plugins()`.

If the config has a non-empty `plugins` list and no extension reads the config, the CLI warns once:
"the config lists plugins, but this cli loads none. Plugin loading moved out of clibuilder 12 into
@clibuilder/plugins: add .use(plugins()) to the cli."

What stays in core: `cli().use()` and `ExtensionContext`, the registry (`defineKey`,
`defineCollectionKey` and `this.registry`), and `mockPluginContext` in
`clibuilder/testing`.

A plugin's `activate(context)` is unchanged, and a plugin built for 11 loads unchanged.
`import type { PluginActivationContext } from 'clibuilder'` still compiles in 12 but is deprecated.
Import it from `@clibuilder/plugins`. `clibuilder` 13 removes it.

The next `@clibuilder/plugins` release (unreleased, a 0.x minor) requires `clibuilder ^12` as a
peer. With `clibuilder` 11, keep using `@clibuilder/plugins` 0.1.0. The 0.1.0 behavior where 11
skips its own loading when `plugins()` is used goes away with core's loading.

Downstream: repobuddy/buddy relies on `cli({ config: true })` loading plugins and needs
`.use(config()).use(plugins())`.

Source:
[slim-dependencies section 9](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/slim-dependencies.md#9-amendment-move-all-plugin-support-out-of-core).

## `@clibuilder/axi` is folded into core

**Available:** [`@clibuilder/axi`](/clibuilder/packages/axi/) 0.2.1.

**Unreleased** (v12): the truncation, count and home helpers are in the
[`clibuilder/axi`](/clibuilder/api/axi/) subpath, and the output, error, usage-error and format parts
are built into core. `@clibuilder/axi` 0.3.0 needs `clibuilder` 12, re-exports the helpers
from `clibuilder/axi`, and marks every export `@deprecated` with its core replacement. `fullOption` is
declared with `t` instead of zod.

**Planned:** the package is deprecated on npm when v12 ships. Until then it is not deprecated, so
keep using it with `clibuilder` 11. Source:
[axi-native section 4.1](https://github.com/clibuilder/clibuilder/blob/main/docs/rfcs/axi-native.md#41-decision-where-clibuilderaxis-contents-belong).
